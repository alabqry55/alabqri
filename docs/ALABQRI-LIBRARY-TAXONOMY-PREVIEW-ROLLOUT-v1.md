# تأسيس التصنيف متعدد المستويات لمكتبة ALABQRI — حزمة Preview v1

- الفرع: `feat/library-taxonomy-preview-foundation`
- نقطة الأساس: `main` عند `19631ae903ff0cbe9aa985a5acea9b06649041fd`
- النطاق: إضافة بنية تصنيف مستقلة دون المساس بجدول `articles`.
- الحالة: **ملفات الترحيل والتحقق جاهزة للمراجعة؛ لم تُنفّذ على أي قاعدة D1 بعد.**

## 1. ما الذي أُنشئ؟

ملف الترحيل:
`migrations/0002_library_taxonomy_foundation.sql`

ينشئ أربع جداول تصنيف مستقلة، ويتأكد أيضًا من وجود جدول سجل التدقيق المساعد:
- `library_sections`: الأقسام السبعة بالترتيب المعتمد.
- `library_specialties`: التخصصات الأربعة عشر.
- `library_content_types`: خمسة أنواع محتوى معتمدة.
- `library_article_classification`: علاقة اختيارية مستقبلية بين المقال وتصنيفه؛ لكل مقال قسم أساسي واحد ونوع محتوى واحد، وتخصص أساسي اختياري.\n- `article_admin_audit`: سجل تدقيق مساعد يُنشأ فقط إذا لم يكن موجودًا؛ وإذا كان موجودًا تُحفظ بياناته كما هي.

ويضيف فهارس على القسم والتخصص ونوع المحتوى وحالة المراجعة.

قاموس أنواع المحتوى الخمسة: «مقال»، «بحث»، «دراسة»، «دورة»، «مادة تدريبية».

## 2. حواجز الأمان

- لا يضيف أعمدة إلى `articles`.
- لا يغيّر `category` أو `tags_json` أو المحتوى أو التاريخ أو SEO.
- لا ينفذ أي `UPDATE` أو `DELETE` أو `ALTER TABLE articles`.
- لا يضيف أي صف إلى `library_article_classification`؛ لذلك لا ينقل أو يصنّف المقالات تلقائيًا.
- لا يحذف أو يعيد تسمية قيم التصنيف القديمة الست.
- التخصص يقبل `NULL` حتى لا نفرض تخصصًا غير ملائم.
- يجب تشغيله على `alabqri-db-preview-test` فقط، بعد التأكد من اسم قاعدة البيانات والنسخة الاحتياطية. **ممنوع تشغيله على `alabqri-db` الإنتاجية في هذه المرحلة.**

## 3. خطوات تشغيل Preview يدويًا

1. افتح Cloudflare D1 واختر قاعدة `alabqri-db-preview-test`، وتحقق من اسمها قبل تنفيذ أي SQL.
2. خذ نسخة احتياطية من قاعدة Preview.
3. افتح ملف الترحيل من المستودع وانسخ محتواه كاملًا.
4. نفّذ SQL مرة واحدة في Console الخاصة بقاعدة Preview فقط.
5. نفّذ استعلامات التحقق في القسم التالي وأرسل النتائج لمراجعتها.
6. لا تنفذ أي ترحيل إضافي ولا تغيّر المقالات قبل مراجعة النتائج.

## 4. استعلامات التحقق بعد الترحيل

### أ. التأكد من عدد عناصر القواميس

```sql
SELECT 'sections' AS item, COUNT(*) AS total FROM library_sections
UNION ALL
SELECT 'specialties', COUNT(*) FROM library_specialties
UNION ALL
SELECT 'content_types', COUNT(*) FROM library_content_types
UNION ALL
SELECT 'article_classification', COUNT(*) FROM library_article_classification;
```

المتوقع في قاعدة Preview النظيفة من هذه الجداول: الأقسام 7، التخصصات 14، أنواع المحتوى 5، وسجلات التصنيف 0.

### ب. مراجعة ترتيب الأقسام

```sql
SELECT id, name, sort_order
FROM library_sections
ORDER BY sort_order;
```

### ج. مراجعة التخصصات

```sql
SELECT id, name, sort_order
FROM library_specialties
ORDER BY sort_order;
```

### د. التأكد من بقاء المقالات القديمة دون تغيير

```sql
SELECT COUNT(*) AS total_articles FROM articles;

SELECT category, COUNT(*) AS total
FROM articles
GROUP BY category
ORDER BY total DESC;
```

قارن النتيجة مع خط أساس قاعدة الإنتاج الذي جرى جرده: 19 سجلًا موزعة على القيم القديمة الخمس الظاهرة في البيانات. لا تفترض أن Preview يطابق الإنتاج قبل رؤية النتيجة.

### هـ. سلامة العلاقات

```sql
PRAGMA foreign_key_check;
```

المتوقع: لا صفوف مخالفة.

### و. التأكد من عدم إنشاء تصنيفات للمقالات تلقائيًا

```sql
SELECT COUNT(*) AS classified_articles
FROM library_article_classification;
```

المتوقع: صفر.

## 5. نقاط لا تزال تحتاج اعتمادًا تحريريًا

هذه البنية لا تحسم قرارات المحتوى:
- تخصص مقال الأذكار غير محسوم؛ لا يوجد تخصص مباشر له في قائمة الأربعة عشر.
- التخصص الدقيق لمقال «رحلة الشفاء الذاتي» يحتاج مراجعة علمية.
- سجلّا الخوف والخشية يحتاجان قرارًا بشأن العنوان والتداخل دون حذف.
- سجل رسالة المركز يحتاج قرار نقله إلى صفحة مؤسسية مستقلة.
- وسوم مقال الذنب وجلد الذات تحتاج اعتمادًا قبل تحديثها.
- لا يُسند أي مقال إلى قسم الحديث الشريف لمجرد وجود استشهاد بحديث.

4. حسم المواد التي لا يناسبها تخصص حالي.
