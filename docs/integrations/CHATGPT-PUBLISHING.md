# ربط ChatGPT بالنشر المعتمد في ALABQRI

## الحالة والحدود

هذا التكامل يتيح لـ ChatGPT إرسال **مقال جديد واحد فقط** بعد موافقة المستخدم الصريحة على النشر. لا يتيح قراءة بيانات الإدارة أو تعديل مقال سابق أو جدولة المقالات أو الحذف أو النشر الجماعي.

- المسار: `POST /api/articles`
- المصادقة: `Authorization: Bearer <CHATGPT_PUBLISH_TOKEN>`
- يجب أن يحتوي الطلب على `publishApproved: true`.
- يتطلب المقال عنوانًا وهوية فريدة؛ التكرار مرفوض.
- يُسجل التدقيق باسم `chatgpt-integration`.
- لا تعني استجابة النجاح إلا أن D1 أعادت المقال وتحققت الخدمة من بياناته.
- يبقى النشر الفعلي متوقفًا إلى أن يُضبط السر في بيئة Cloudflare وتُربط أداة ChatGPT المعتمدة.

## إعداد السر

1. أنشئ قيمة عشوائية قوية لا تقل عن 32 حرفًا (ويُفضّل 32 بايت عشوائية أو أكثر).
2. في Cloudflare Dashboard افتح Workers & Pages ثم مشروع Pages `alabqri`.
3. أضف متغيرًا سريًا باسم `CHATGPT_PUBLISH_TOKEN` في **Preview** أولًا، وليس Production.
4. استخدم القيمة نفسها في إعداد مصادقة Bearer API Key داخل أداة ChatGPT التي ستربطها.
5. لا تضع السر في ملفات المستودع أو رسائل المحادثة أو كود الواجهة. لا تستخدم سر Preview في Production.

مثال لتوليد سر محليًا على Windows PowerShell:
```powershell
$bytes = New-Object byte[] 48
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
[Convert]::ToBase64String($bytes)
$rng.Dispose()
```

## إعداد أداة ChatGPT

استورد مخطط OpenAPI من `chatgpt-article-publishing.openapi.yaml` في أداة تدعم Actions/OpenAPI، واضبط المصادقة على API Key من نوع Bearer. فعّل تأكيد المستخدم لكل استدعاء إن كان الخيار متاحًا، واترك العملية مصنفة كتغيير مؤثر.

تعليمات الأداة يجب أن تنص على:
- لا تستدعِ النشر عند تجهيز مقال أو مراجعته أو عند قول المستخدم «احفظ كمسودة».
- لا تستدعِ النشر إلا بعد أمر واضح وصريح من المستخدم مثل «انشر المقال».
- أرسل المقال الحالي الذي راجعه المستخدم فقط.
- لا تعاود إرسال الطلب بعد استجابة غامضة قبل الاستعلام أو التحقق من النتيجة، لأن التكرار مرفوض عمدًا.

قد تختلف إمكانية إنشاء Actions أو ربط موصل مخصص بحسب خطة ChatGPT وإعدادات مساحة العمل. وجود API في الموقع وحده لا ينشئ اتصالًا تلقائيًا من المحادثة.

## ملاحظة Cloudflare Access

ظهر أن عنوان المعاينة يطلب تسجيل دخول تفاعليًا. إذا كانت سياسة Cloudflare Access تحمي عنوان Pages، فلن يستطيع اتصال ChatGPT الخادمي إكمال صفحة تسجيل الدخول التفاعلية. عند اختبار Actions:
- لا تعطّل Cloudflare Access عن الموقع كله.
- استخدم Service Auth إذا كانت أداة الاتصال تدعم إرسال ترويسات Cloudflare المطلوبة؛ أو أنشئ استثناءً ضيقًا للمسار `/api/articles` على عنوان المعاينة فقط.
- حتى عند السماح بالوصول إلى هذا المسار، يظل `CHATGPT_PUBLISH_TOKEN` إلزاميًا داخل Pages Function، ولا يسمح الخادم بأي عملية دون Bearer token صحيح وموافقة نشر صريحة.
- لا تكرر الاستثناء على Production قبل مراجعة السياسة الأمنية واختبارها.

## اختبار المعاينة

قبل أي تفعيل إنتاجي:
1. اضبط السر في بيئة Preview فقط.
2. اختبر رفض الطلب بلا سر وبسر خاطئ.
3. اختبر رفض الطلب دون `publishApproved: true`.
4. اختبر رفض الحذف والجدولة والتعديل والتكرار.
5. اختبر نشر مقال تجريبي جديد، ثم تحقق من `verified: true` وظهوره في مكتبة المعاينة.
6. اختبر عدم تغير مقالات الإنتاج أو قاعدة بيانات الإنتاج.

لا تنقل السر إلى Production ولا تدمج التغيير قبل موافقة مالك المنصة ونجاح اختبارات المعاينة.
