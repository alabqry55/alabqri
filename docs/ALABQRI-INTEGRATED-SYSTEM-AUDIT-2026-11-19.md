## 1. ملخص تنفيذي

أظهر فحص شجرة المستودع وملفات المكتبة وواجهة API ومخطط D1 والاختبارات والوثائق القانونية ما يلي:

1. المنصة تطبيق Cloudflare Pages/Functions مع واجهة رئيسية كبيرة في `index.html`، وملفات JavaScript/CSS مستقلة لبعض الوظائف.
2. مكتبة المقالات موجودة فعليًا، وتعرض ستة أقسام، مع بقاء قيم التصنيف المخزنة القديمة.
3. واجهة API تقبل ست قيم تصنيف حاليًا، وتنفذ القراءة العامة عبر GET دون DDL أو كتابة وفق اختبارات الانحدار.
4. إدارة المقالات مرتبطة بجلسة GitHub OAuth للمالك، واختبارات الأمان تغطي رفض الكتابة غير المصرح بها والتحقق من الجلسة وOrigin.
5. قاعدة البيانات في `schema.sql` تصف بنية أساسية، بينما تضيف API أعمدة وحقولًا وجداول مساعدة أثناء عملية كتابة مصادق عليها؛ لذلك لا يكفي الملف وحده لإثبات مخطط D1 الفعلي.
6. لا توجد في شجرة الملفات ملفات مستقلة واضحة تحمل أسماء منظومة البوصلة أو المصفوفة أو المؤشر أو الخريطة أو ميزان سلامة الوصول. هذا لا يثبت غيابها؛ فقد تكون أقسامًا مضمّنة في `index.html` الكبير، ولم يتسن فحص محتواه كاملًا من خلال قارئ المستودع.
7. توجد سياسة شهادات وبوابة توثيق وشروط استخدام وسياسة خصوصية وإخلاء مسؤولية، لكنها لا تثبت وحدها صحة أو نطاق أي اعتماد خارجي للبرامج.
8. تعذر استكمال فحص الموقع تفاعليًا وقراءة D1 الحية في هذه الجلسة؛ ولذلك لا توجد أرقام موثقة لعدد سجلات المقالات أو نتيجة اختبار تشغيل حي للأدوات.

**القرار:** الاستمرار في مرحلة الجرد والتصميم. لا تغيير لتصنيفات الإنتاج ولا ترحيل D1 ولا دمج تغييرات وظيفية قبل استكمال الأدلة الحية.

## 3. جرد المكتبة والتصنيفات

### 3.1 ما هو موجود
- مكتبة مقالات في `assets/articles-library.js`.
- ست بطاقات أقسام في مصفوفة `librarySections`.
- بحث في العنوان والملخص والمحتوى والتصنيف والوسوم.
- تصفية بحسب القسم.
- بطاقات تعرض العنوان والتصنيف والتاريخ والوسوم.
- اتصال بواجهة `/api/articles`.
- الحفاظ على قائمة المقالات القديمة إلى أن تصل استجابة API صالحة.
- إزالة عناصر البحث/التصفية القديمة ضمن نطاق تبويب المقالات فقط.
- بوابة إدارة مرتبطة بجلسة المالك.

### 3.2 الأقسام الستة الظاهرة حاليًا في الكود
1. القرآن الكريم وعلومه — القيمة المخزنة `القرآن الكريم وعلومه`.
2. الذكر والاتزان الإيماني — القيمة المخزنة `الأذكار والاتزان`.
3. علم النفس الإسلامي والتنمية البشرية — القيمة المخزنة `التنمية البشرية`.
4. الطب التكميلي والتوعية الصحية — القيمة المخزنة `الطب التكميلي`.
5. الأبحاث والدراسات — القيمة المخزنة `البحث العلمي`.
6. المعرفة والفكر — القيمة المخزنة `موضوعات معرفية`.

### 3.3 ملاحظة تحتاج حسمًا
ملف `docs/articles-library-v2-spec.md` يصف قسم القرآن بأنه «قريبًا» ويذكر عدم السماح بإنشاء تصنيف جديد، لكن مصفوفة الأقسام الحالية في `assets/articles-library.js` تربطه بقيمة تصنيف فعلية ولا تضبط له `comingSoon` في المقطع المفحوص. يلزم فحص السلوك الفعلي قبل اعتماد وصفه أو تغيير حالته.

كما أن نص المواصفات القديمة يذكر «قيم التصنيف الخمس» في موضع، بينما قائمة API والاختبارات ومصفوفة الواجهة تكشف ست قيم/أقسام. هذه نقطة توثيقية غير متسقة ينبغي تصحيحها في تحديث مستقل بعد تأكيد كل القيم.

### 3.4 قيم التصنيف المقبولة في API
القائمة المرصودة في `functions/api/articles.js`:
- القرآن الكريم وعلومه
- التنمية البشرية
- الطب التكميلي
- الأذكار والاتزان
- البحث العلمي
- موضوعات معرفية

كل من عمليتي `save` و`saveMany/seedSchedule` تتحقق من عضوية التصنيف في قائمة السماح. لذلك فإن إضافة القسم السابع أو تغيير أسماء القيم في واجهة المستخدم وحدها لن يكفي؛ يجب أن تتوافق واجهة الإدارة وواجهة المكتبة وAPI والتحقق والاختبارات معًا.

## 4. جرد D1 من المصدر البرمجي — وليس من القاعدة الحية

### 4.1 ما يصفه `schema.sql`
- جداول الزوار والجلسات اليومية.
- جداول التقييمات والتفاعل.
- جدول المشتركين.
- جدول `articles` الأساسي، وفيه: id, title, category, date, excerpt, content, created_at, updated_at.

### 4.2 ما تضيفه API عند الكتابة المصادق عليها
يحتوي `functions/api/articles.js` على تهيئة/إضافة حقول عند POST، منها:
- `scheduled_at`
- `tags_json`
- `seo_title`
- `seo_description`
- `seo_keywords`
- `canonical_url`
- `og_image`

كما توجد تهيئة لجدول `article_admin_audit` وفهرس له. وتوضح الاختبارات أن GET يجب أن يظل SELECT فقط ولا ينفذ DDL أو DML.

### 4.3 ما لا نعرفه دون اتصال قراءة مباشر بقاعدة D1
- العدد الحالي الدقيق للمقالات.
- عدد المقالات في كل تصنيف.
- القيم الفعلية الموجودة في عمود category.
- وجود كل الأعمدة المساعدة في قاعدة الإنتاج.
- عدد سجلات التدقيق.
- وجود أي سجلات أو بيانات أخرى مرتبطة بأدوات الاتزان.

لم تتوفر في هذه الجلسة أداة موصولة لتنفيذ SELECT على قاعدة Cloudflare D1 الإنتاجية، ولم يتم استخدام أي استعلام كتابة. لا يجوز استبدال هذا النقص بتخمين أو بالاعتماد على `schema.sql` وحده.

## 5. جرد الإدارة والأمان والاختبارات

### 5.1 ما تؤكده الملفات
- واجهة الإدارة تتحقق من `/api/admin/github/session` وتحوّل إلى OAuth عند غياب جلسة المالك.
- الاختبارات تمنع الاعتماد على `ARTICLES_ADMIN_KEY` أو `X-Admin-Key` في الواجهة.
- جلسة الإدارة تختبر هوية GitHub للمالك `alabqry55` ومعرّفه الرقمي.
- اختبارات ترفض جلسة معدلة التوقيع أو منتهية أو مرتبطة بهوية أخرى.
- اختبارات ترفض POST دون جلسة مالك قبل لمس D1.
- اختبارات ترفض الطلبات العابرة للمصدر وContent-Type غير المناسب.
- اختبارات تؤكد أن GET للمقالات لا ينفذ إلا SELECT.
- توجد اختبارات انحدار صريحة تتوقع الأقسام الستة وقيم التخزين الست الحالية.
- توجد اختبارات لمنع تكرار تحميل واجهة المكتبة وبوابة OAuth.

### 5.2 حالة سير الاختبارات
- سير العمل `.github/workflows/security-checks.yml` يشغل `npm run test:security`.
- مسارات تشغيله تشمل ملفات المصادقة وAPI المقالات ومكتبة المقالات والاختبارات وملف package.
- شوهدت نتائج نجاح حديثة لسير الأمان على PR #117، لكنها ليست اختبارًا لفرع وثيقة المنظومة PR #118.
- فحص Cloudflare Pages على commit وثيقة PR #118 نجح في بناء/نشر المعاينة، لكنه لا يساوي نجاح اختبارات الأمان أو الوظائف.

لا أصف اختبارات PR #118 بأنها ناجحة؛ لا يوجد في سجل الفحوص الذي تمت مراجعته تشغيل Security Checks مرتبط به.

- لا توجد ملفات مستقلة ظاهرة في شجرة المستودع لأدوات: البوصلة، المصفوفة، المؤشر، الخريطة، ميزان سلامة الوصول.

- نظرًا إلى تعذر فحص كامل `index.html`، تصنيف هذه الأدوات الحالي هو **غير متحقق منه**، لا «غير موجود قطعًا».

المطلوب في المرحلة التالية: فحص مقاطع الصفحة الرئيسية ومصادر JavaScript المرتبطة بها، وتحديد IDs والأحداث والبيانات المخزنة ومسارات الحفظ، ثم اختبار الوظائف على Preview دون بيانات شخصية.

## 10. خطة استكمال الجرد — دون تغيير الإنتاج

### الخطوة أ — استكمال فحص الصفحة الرئيسية
- قراءة `index.html` محليًا أو عبر أداة تدعم الملف الكبير.
- استخراج جميع IDs وanchors وعناوين الأقسام وأسماء النوافذ والأدوات.
- استخراج روابط JavaScript ومطابقة كل عنصر بملف تنفيذه.
- إعداد خريطة التنقل الثمانية الحالية.

### الخطوة ب — جرد D1 قراءة فقط
تنفذ من اتصال Cloudflare موثوق وبصلاحية قراءة، بعد التأكد من قاعدة `alabqri-db` وبيئة production. الاستعلامات المقترحة:
- `PRAGMA table_info(articles)`
- `SELECT category, COUNT(*) AS total FROM articles GROUP BY category ORDER BY category`
- `SELECT COUNT(*) AS total FROM articles`
- `SELECT id,title,category,date,updated_at FROM articles ORDER BY updated_at DESC LIMIT 30`
- `SELECT action,COUNT(*) AS total FROM article_admin_audit GROUP BY action` بعد التأكد من وجود الجدول.

يجب عدم إظهار محتوى المقالات كاملًا في تقرير الجرد إلا عند الحاجة، والاكتفاء بالمعرف والعنوان والتصنيف والتاريخ.

### الخطوة ج — فحص البرامج والاتزان
- فحص أقسام `#diplomas` و`#courses` و`#consultations` في الصفحة الرئيسية.
- تحديد هل أدوات المرصد موجودة كواجهات فعلية أو مجرد روابط/وصف.
- اختبار تدفق المستخدم دون حفظ بيانات شخصية.
- جرد حقول البرنامج والشهادة والاعتماد كما تظهر فعليًا.

### الخطوة د — تقرير الفجوات النهائي
بعد اكتمال أ، ب، ج، يصدر تقرير نهائي يميز:
- موجود ويعمل.
- موجود ويحتاج تطويرًا.
- موجود في المصدر وغير متحقق حيًا.
- غير موجود.
- يحتاج قرارًا تحريريًا/علميًا/قانونيًا.
