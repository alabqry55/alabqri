## 1. الغرض والنطاق

تحدد هذه الوثيقة الإطار المؤسسي والمعرفي والتعليمي والتقني الموحد للمنصة، وتضع أساسًا مرحليًا لتطويرها دون إعادة بناء ما يعمل بالفعل أو تعريض المحتوى المنشور أو قاعدة البيانات أو صلاحيات الإدارة للخطر.

تتكون المنظومة من أربعة أركان مترابطة:
1. المعرفة والبحث.
2. التعليم والتأهيل.
3. السكينة والاتزان الشامل.
4. التقنية والإعلام والخدمات.

ويعمل **ميزان العبقري لسلامة الوصول** مرجعية منهجية عابرة للأركان الأربعة.

### خارج نطاق الإصدار 1.0
- لا تعديل على واجهة الإنتاج أو ملفات التطبيق.
- لا تغيير على قاعدة D1 أو تشغيل أي ترحيل بيانات.
- لا إضافة أو حذف تصنيفات فعلية في الإنتاج.
- لا تغيير في OAuth أو الصلاحيات أو إعدادات Cloudflare.
- لا اعتماد أو نشر ادعاءات علاجية أو مهنية أو أكاديمية غير موثقة.

## 3. الركن الأول: المعرفة والبحث

### 3.1 الأقسام الرئيسية المستهدفة

الترتيب المعتمد في التصور المستهدف:

1. القرآن الكريم وعلومه.
2. الحديث الشريف وعلومه.
3. الذكر والإتزان الإيماني.
4. علم النفس الإسلامي والتنمية البشرية.
5. الطب التكميلي والتوعية الصحية.
6. الأبحاث والدراسات.
7. المعرفة والفكر.

يجب أن يبقى الحديث الشريف وعلومه في المرتبة الثانية مباشرة بعد القرآن الكريم.

### 3.2 التخصصات الأربعة عشر المقترحة

1. علوم القرآن الكريم.
2. علوم السنة النبوية.
3. علوم الإعجاز العددي والبياني في القرآن الكريم.
4. علوم الحكمة المحمدية.
5. علوم الحكمة السليمانية.
6. علوم الأسماء والدعوات والرقى.
7. علوم الطاقة الإنسانية.
8. علوم الطاقة الكونية.
9. علوم الطاقة الروحية.
10. علوم الريكي الإسلامي.
11. علوم اللمسة الشفائية.
12. علوم العلاج عن بعد.
13. علوم الحياة وهندسة الجودة والتوازن الشامل.
14. منهج العبقري في سلامة الوصول.

هذه قائمة تخصصات مقترحة من صاحب المنصة، وليست إقرارًا مسبقًا بالتكافؤ العلمي أو الطبي لجميع المصطلحات. يلزم لكل تخصص تعريف تحريري وحدود موضوعية ومراجعة شرعية/علمية/مهنية قبل عرضه بوصفه مجالًا معرفيًا أو تدريبيًا.

### 3.3 نموذج التصنيف المقترح

يُفصل بين أربعة مفاهيم:
- **القسم الرئيسي:** مجال التصفح الأساسي.
- **التخصص:** المجال الموضوعي الدقيق، ويمكن أن يرتبط بأكثر من قسم.
- **نوع المحتوى:** مقال، بحث، دراسة، مرجع، مادة تعليمية، أو غير ذلك.
- **الوسوم:** كلمات مساعدة للبحث والاستكشاف.

لكل مادة قسم رئيسي أساسي وتخصص أساسي عند انطباقه، مع السماح بعلاقات إضافية متعددة عند الحاجة. لا يُستخدم قسم «الأبحاث والدراسات» بديلًا عن نوع المحتوى في نموذج البيانات؛ ويمكن الاحتفاظ به كمدخل تصفح رئيسي لأغراض تجربة المستخدم.

### 3.4 قواعد حوكمة المحتوى
- القرآن الكريم والحديث الشريف: توثيق النصوص والمصادر والتمييز بين الصحيح والضعيف والشرح والرأي.
- الموضوعات الصحية والتكميلية: التمييز بين الدليل السريري والممارسة التقليدية والفرضية والرأي، وعدم تقديمها بديلًا عن الرعاية الطبية.
- الموضوعات النفسية: عدم تحويل مواد التثقيف أو التدريب إلى تشخيص أو علاج نفسي دون اختصاص وترخيص.
- الإعجاز العددي والبياني: بيان المنهج والمراجع وحدود الاستنتاج، وتجنب القطع بما لا يثبت.
- عدم اعتماد مصطلح تخصصي نهائيًا قبل تحرير تعريفه ونطاقه.

## 4. الركن الثاني: التعليم والتأهيل

يضم:

- ملفات المتدربين وسجلات الإنجاز.

### 4.1 الدبلومات والبرامج
تُعامل الدبلومات بوصفها برامج أكاديمية/تدريبية مرتبطة بتخصص واحد أو أكثر، لا تصنيفات مكتبية جديدة. تشمل قائمة البرامج التي سبق طرحها:
- العلاج بالرقية الشرعية.
- العلاج بالطاقة الحيوية.
- العلاج بالريكي الإسلامي.
- علم السوجوك والتأهيل الانعكاسي.
- تنمية الذات والمهارات.
- الإرشاد الأسري والتربوي.
- البرمجة اللغوية العصبية.
- الطب البديل والتكميلي.
- العلاج باللمسة الشفائية.
- آليات التحكم النفس عصبي الشاملة ومنظومة الوعي الإنساني.

هذه أسماء برامج قيد المراجعة التحريرية والمهنية، وليست إثباتًا للاعتماد أو الأهلية السريرية.

### 4.2 الحد الأدنى لبطاقة كل برنامج
- الاسم والوصف والأهداف ومخرجات التعلم.
- الفئة المستهدفة وشروط القبول والمتطلبات السابقة.
- الخطة والمستويات والساعات والمدة.
- المحاور والتطبيقات والمراجع.
- التقييم ومشروع التخرج.
- الجهة المانحة للشهادة ونوعها.
- مستند الاعتماد ونطاقه ورقمه وصلاحيته، إن وجد.
- بيان واضح لما تسمح به الشهادة وما لا تسمح به مهنيًا.

لا يثبت السجل التجاري وحده اعتمادًا أكاديميًا أو دوليًا، ولا تمنح دورة تدريبية بذاتها ترخيصًا لممارسة مهنة صحية أو نفسية.

## 5. الركن الثالث: السكينة والاتزان الشامل

المسمى المقترح للبوابة:
**منظومة العبقري للسكينة والاتزان الشامل**

وتتكون من خمس أدوات مترابطة:

1. **بوصلة العبقري:** استكشاف أولي للموقع والاتجاه والأولويات.
2. **مصفوفة العبقري:** تقييم إرشادي متعدد الأبعاد بمعايير معلنة.
3. **مؤشر العبقري للاتزان:** متابعة التغير عبر الزمن لكل بُعد، دون اختزال الشخص في رقم كلي مضلل.
4. **خريطة العبقري للتطور:** تحويل النتائج إلى أهداف وخطوات ومراجعات زمنية.
5. **ميزان العبقري لسلامة الوصول:** مراجعة المنهج والمعلومة وحدود التطبيق عبر الرحلة كلها.

### 5.1 منهج سلامة الوصول
المراحل الست المقترحة:
1. التصور الصحيح.
2. التثبت.
3. التأصيل.
4. الفهم.
5. التدرج.
6. التطبيق.

### 5.2 ضوابط القياس والخصوصية
- الأدوات إرشادية وتطويرية وليست أدوات تشخيص طبي أو نفسي.
- تعريف كل بُعد ومؤشر وطريقة احتسابه ومصدره وحدوده.
- إظهار التغير لكل بُعد، مع توضيح البيانات الناقصة وعدم المبالغة في الدقة.
- عدم استخدام نتائج التقييم لاتخاذ قرارات عالية المخاطر.
- حماية النتائج الشخصية، وتحديد صلاحيات الوصول والاحتفاظ والحذف والموافقة.
- لا تُرسل بيانات التقييم إلى مساعد ذكي أو طرف ثالث إلا وفق غرض معلن وموافقة وضوابط مناسبة.

## 7. العلاقة بين الأركان

- مادة معرفية يمكن أن تقود إلى مقرر أو برنامج تعليمي.
- التخصص يمكن أن يرتبط بعدة مواد وبرامج ومراجع.
- البرنامج التعليمي يستند إلى مكتبة ومراجع ويقيس مخرجات تعلمه.
- البوصلة والمصفوفة تساعدان على تحديد احتياج تطويري، ثم المؤشر والخريطة للمتابعة.
- ميزان سلامة الوصول يراجع المحتوى والبرنامج والتوجيه والتطبيق.
- التقنية والإعلام يقدمان الوصول والخدمات، ولا يحلان محل المرجعية العلمية أو المهنية.

## 8. الوضع التقني المرصود في مستودع ALABQRI

### 8.1 نقطة الأساس التي جرى فحصها
- المستودع: `alabqry55/alabqri`.
- الفرع الافتراضي: `main`.
- آخر commit مرصود أثناء إعداد الوثيقة: `19631ae903ff0cbe9aa985a5acea9b06649041fd`.
- رسالة الدمج: PR #116 — إظهار الأقسام الستة في لوحة إدارة المقالات القديمة.
- المشروع يستخدم HTML وJavaScript وCloudflare Pages Functions وD1.
- الصفحة الرئيسية `index.html` كبيرة ومركزية؛ يجب التعامل معها بحذر وبأقل تغييرات ممكنة.
- ملفات مكتبة المقالات: `assets/articles-library.js`.
- API المقالات: `functions/api/articles.js`.
- مخطط D1 المرجعي في المستودع: `schema.sql`.
- اختبارات الأمان والانحدار: `tests/security/`.
- لا يظهر مجلد migrations مستقل في شجرة الملفات التي فُحصت.

### 8.2 ملاحظات مؤكدة من المصدر
1. ملف مواصفات المكتبة الحالي `docs/articles-library-v2-spec.md` يصف ستة أقسام، ويذكر أن أسماء الأقسام المعروضة مرتبطة مؤقتًا بقيم تصنيف مخزنة قديمة.
2. واجهة API في `functions/api/articles.js` تقبل حاليًا ست قيم فقط للتصنيف عبر قائمة سماح (allowlist).
3. اختبار `tests/security/articles-regression.test.mjs` يثبت توقع الأقسام الستة في لوحة الإدارة القديمة.
4. جدول `articles` في `schema.sql` يستخدم حقل `category` نصيًا، ولا يحتوي هذا الملف وحده على نموذج مستقل للأقسام أو التخصصات.
5. API المقالات يحتوي على تهيئة/إضافة أعمدة عند عملية كتابة مصادق عليها؛ لذلك لا يجوز اعتبار `schema.sql` وحده وصفًا كاملًا لكل الحالة الحية.
6. توجد بالفعل مكتبة مقالات مخصصة وواجهات إدارة تعتمد جلسة GitHub OAuth للمالك.
7. توجد اختبارات تؤكد أن قراءة المقالات GET لا تنفذ DDL أو كتابة في D1، وأن إدارة المقالات تستخدم جلسة المالك بدل مفتاح إداري مكشوف.

### 8.3 ما لم يتم التحقق منه بعد
- حالة قاعدة D1 الإنتاجية الفعلية وجرد سجلاتها.
- تطابق مخطط الإنتاج مع `schema.sql` والتهيئات الديناميكية.
- الحالة الفعلية لجميع صفحات المنصة على الإنتاج.
- وجود الأدوات الخمس لمنظومة الاتزان وتشغيلها في الإنتاج.
- الحالة التفصيلية للدبلومات والاعتمادات وسجلاتها.
- إعدادات Cloudflare Pages والبيئات والأسرار.
- اختبارات الهاتف الفعلية وقياسات الأداء الحالية.

هذه النقاط تبقى «غير متحقق منها» ولا يجوز تحويلها إلى استنتاجات مؤكدة.

## 10. مبادئ تصميم البيانات المستهدفة

هذا تصور منطقي أولي، وليس SQL جاهزًا للتنفيذ:

- `articles`: المحتوى الأساسي مع الاحتفاظ بالمعرفات والروابط والحقول الحالية.
- `categories`: الأقسام الرئيسية بمعرف ثابت واسم وترتيب وحالة.
- `specializations`: التخصصات بمعرف ثابت وتعريف ونطاق ومراجعة تحريرية.
- `article_specializations`: ربط متعدد بين المقالات والتخصصات.
- `article_tags`: الوسوم عند الحاجة إلى تطبيعها، أو إبقاؤها بصيغتها الحالية مرحليًا.
- `content_types`: أنواع المواد مثل مقال وبحث ودراسة ومادة تعليمية.
- `programs`: الدبلومات والدورات.
- `program_specializations`: ربط البرامج بالتخصصات.
- `program_content`: ربط البرامج بالمراجع والمواد التعليمية.
- `assessment_dimensions` و`assessment_sessions` و`assessment_results`: لا تُنشأ قبل اعتماد منهج القياس وسياسة الخصوصية.

### قواعد الترحيل
- لا حذف ولا إعادة إنشاء لجدول المقالات.
- لا تغيير لمعرف مقال أو slug أو تاريخ أو محتوى بسبب تغيير التصنيف.
- إنشاء نسخ احتياطية قابلة للاستعادة قبل أي migration.
- استخدام معرفات تصنيف ثابتة بدل الاعتماد طويلًا على الاسم العربي النصي.
- إعداد خريطة تحويل صريحة من القيم الست الحالية إلى معرفات الأقسام الجديدة.
- لا تُرحّل أي مادة إلى قسم الحديث الشريف أو تخصص جديد بالتخمين؛ تُراجع كل مادة ملتبسة.
- تشغيل الترحيل في بيئة preview أولًا، والتحقق من أعداد السجلات والعينات والروابط.
- توفير rollback موثق واختبار عملي له قبل الإنتاج.

## 11. مراحل التنفيذ المعتمدة

### المرحلة 0 — التوثيق والجرد
- اعتماد هذه الوثيقة مرجعًا أوليًا.
- استكمال جرد ملفات الواجهة والـ API والاختبارات.
- جرد D1 الفعلي قراءة فقط.
- فحص الأدوات الخمس والدبلومات والصفحات الحية.
- إصدار تقرير واقع نهائي مع روابط الملفات والأدلة.

### المرحلة 1 — التصميم التفصيلي
- إعداد خريطة صفحات ومكونات.
- اعتماد تعريفات الأقسام السبعة والتخصصات الأربعة عشر.
- اعتماد أنواع المحتوى والوسوم.
- إعداد mapping لكل قيمة تصنيف قديمة ولكل مادة.
- اعتماد نموذج البرامج والاعتماد.
- اعتماد تعريفات أبعاد الاتزان ومؤشراته وسياسة الخصوصية.

### المرحلة 2 — نموذج أولي غير إنتاجي
- تنفيذ نموذج بيانات/واجهة في فرع منفصل.
- عدم تشغيل migrations على الإنتاج.
- الحفاظ على توافق API والواجهة القديمة خلال الانتقال.
- إضافة اختبارات تغطي الأقسام والتخصصات والبحث والحفظ والجدولة والصلاحيات.

### المرحلة 3 — المعاينة والاختبارات
- اختبارات API وD1 في preview.
- اختبارات OAuth والمالك وتسجيل الخروج.
- اختبارات عدم فقد المقالات وعدم تكرارها.
- اختبارات الروابط والبحث والتصفية والهواتف.
- مراجعة بشرية للتصنيف والمواد الملتبسة.

### المرحلة 4 — موافقة الإنتاج والترحيل
- لا تبدأ إلا بعد نجاح المعاينة وموافقة المالك.
- نسخ احتياطي وتحقق من إمكانية الاستعادة.
- ترحيل تدريجي قابل للرجوع.
- التحقق بعد النشر من عدد السجلات والمقالات والروابط والصلاحيات.

### المرحلة 5 — التوسع الوظيفي
- استكمال البرامج التعليمية وسجلات المتدربين.
- استكمال منظومة الاتزان وأدواتها.
- إدخال المساعد الذكي وفق الحوكمة.
- تحسين الإعلام والخدمات والقياس.

## 12. بوابات القبول قبل أي نشر

لا يُسمح بالانتقال للإنتاج ما لم تتحقق جميع الشروط ذات الصلة:
- عدم وجود فقد أو تعديل غير مقصود للمحتوى.
- تطابق أعداد المقالات قبل/بعد الترحيل، مع تفسير أي فرق.
- نجاح القراءة والحفظ والتحرير والجدولة.
- نجاح OAuth للمالك `alabqry55` فقط.
- فشل محاولات الكتابة غير المصرح بها.
- عدم ظهور أدوات الإدارة بعد تسجيل الخروج.
- نجاح البحث والتصفية على الأقسام والتخصصات.
- نجاح العرض على الحاسوب والهاتف.
- عدم وجود أخطاء Console أو API حرجة.
- وجود نسخة احتياطية واختبار استعادة موثق.
- مراجعة المعاينة وموافقة المالك الصريحة.
