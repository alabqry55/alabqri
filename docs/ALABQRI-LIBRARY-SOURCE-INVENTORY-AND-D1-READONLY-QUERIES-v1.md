## 1. خلاصة التنفيذ

تمت مراجعة الملفين التاليين من فرع `main`:

- `assets/articles-library.js` — SHA: `6799a1183d04862e064a1099e286c38eb75f7ca1`
- `functions/api/articles.js` — SHA: `7801dc424b8e49391cebc1657cc39bcc75abbad7`

ولم يظهر ضمن الاتصالات المتاحة في جلسة العمل اتصال Cloudflare D1 موثوق يتيح تنفيذ استعلامات قراءة على قاعدة الإنتاج. لذلك لم تُنفذ استعلامات على D1، ولم تُستخرج أعداد المقالات الفعلية، ولم تُنشأ خريطة تحويل نهائية للمقالات.

## 2. ما ثبت من المصدر البرمجي

### 2.1 قيم التصنيف القديمة المقبولة في API

يحتوي `functions/api/articles.js` على مجموعة `CATEGORIES` التالية:

1. `القرآن الكريم وعلومه`
2. `التنمية البشرية`
3. `الطب التكميلي`
4. `الأذكار والاتزان`
5. `البحث العلمي`
6. `موضوعات معرفية`

ويعرض `assets/articles-library.js` ستة أقسام تصفح تقابل هذه القيم. هذا يثبت القيم المقبولة في المصدر المفحوص، ولا يثبت أن كل قيمة منها مستخدمة حاليًا في D1.

### 2.2 القسم السابع المستهدف

«الحديث الشريف وعلومه» غير موجود ضمن مجموعة `CATEGORIES` المفحوصة في API، ولا ضمن مصفوفة أقسام التصفح الستة في ملف المكتبة. يجب عدم إضافته وظيفيًا قبل اعتماد نموذج التوافق وخطة الترحيل والاختبارات.

### 2.3 الحقول التي تقرؤها API

مسار GET يحاول قراءة الحقول التالية من جدول `articles`:

- `id`
- `title`
- `category`
- `date`
- `excerpt`
- `content`
- `scheduled_at`
- `tags_json`
- `seo_title`
- `seo_description`
- `seo_keywords`
- `canonical_url`
- `og_image`
- `created_at`
- `updated_at`

ويحتوي المصدر على توافق رجعي عند غياب بعض الأعمدة، كما أن بعض الأعمدة تُضاف عند عملية كتابة مصادق عليها. لذلك يجب مقارنة هذا الوصف بمخطط D1 الحي قبل تصميم أي migration.

### 2.4 مادة مرجعية معرفة في المصدر

توجد مادة مرجعية باسم/معرف `azkar-balance` بعنوان «🌿 أثر الأذكار في الاتزان النفسي» وتصنيفها القديم `الأذكار والاتزان`. وجودها في كود API لا يثبت وحده أنها سجل محفوظ في D1؛ فالـ API قد تعرضها كعنصر مرجعي عند غياب سجل مطابق.

### 2.5 طريقة القراءة

مسار GET في API يقرأ سجلات `articles`، ويخفي المقالات المجدولة مستقبلًا عن الزائر العام، بينما يستطيع المالك المصادق عليه رؤية السجلات المجدولة. كما ينفذ مسار GET ترشيحًا وتوحيدًا لبعض المواد المرجعية والتكرارات في طبقة العرض؛ لذا لا ينبغي اعتبار استجابة الواجهة العامة وحدها نسخة خامًا كاملة من سجلات الجدول.

## 3. حزمة استعلامات D1 — SELECT فقط

**شرط التنفيذ:** افتح قاعدة الإنتاج `alabqri-db` تحديدًا في Cloudflare D1، وتأكد من اسم القاعدة والبيئة قبل التنفيذ. لا تستخدم قاعدة Preview بدل الإنتاج، ولا تنفذ أي أمر كتابة أو DDL.

### الاستعلام 0 — التحقق من أعمدة الجدول قبل بقية الاستعلامات

```sql
PRAGMA table_info(articles);
```

هذا أمر وصف بنية للقراءة فقط. راجع وجود `scheduled_at` وحقول SEO والوسوم قبل تشغيل الاستعلامات التالية. يدعم API مخططات أقدم قد تفتقد بعض هذه الأعمدة؛ إذا غاب عمود، احذفه من قائمة SELECT/شرط الاستعلام المعني ولا تنفذ ALTER لإضافته أثناء الجرد.

### الاستعلام 1 — عدد السجلات بحسب التصنيف والحالة الزمنية

```sql
SELECT
  category,
  COUNT(*) AS total_articles,
  SUM(CASE
    WHEN scheduled_at IS NULL OR TRIM(scheduled_at) = '' THEN 1
    WHEN julianday(scheduled_at) <= julianday('now') THEN 1
    ELSE 0
  END) AS currently_due_or_unscheduled,
  SUM(CASE
    WHEN scheduled_at IS NOT NULL
     AND TRIM(scheduled_at) <> ''
     AND julianday(scheduled_at) > julianday('now') THEN 1
    ELSE 0
  END) AS scheduled_future
FROM articles
GROUP BY category
ORDER BY category;
```

### الاستعلام 2 — كل السجلات اللازمة لمراجعة التصنيف

```sql
SELECT
  id,
  title,
  category,
  date,
  excerpt,
  content,
  scheduled_at,
  tags_json,
  seo_title,
  seo_description,
  seo_keywords,
  canonical_url,
  og_image,
  created_at,
  updated_at
FROM articles
ORDER BY category, updated_at DESC, created_at DESC, id;
```

هذا الاستعلام يعيد المحتوى الكامل، وقد تكون النتيجة كبيرة. إذا تجاوزت واجهة Cloudflare حد العرض، استخرجها على دفعات باستخدام حدود `LIMIT` و`OFFSET` ثابتة، مع حفظ قيمة `id` لكل سجل وعدم إسقاط أي صف.

### الاستعلام 3 — القيم التصنيفية الموجودة فعليًا

```sql
SELECT
  COALESCE(NULLIF(TRIM(category), ''), '[قيمة فارغة]') AS category_value,
  COUNT(*) AS article_count
FROM articles
GROUP BY COALESCE(NULLIF(TRIM(category), ''), '[قيمة فارغة]')
ORDER BY article_count DESC, category_value;
```

### الاستعلام 4 — السجلات ذات الحقول التصنيفية الناقصة أو غير المتوقعة

```sql
SELECT id, title, category, date, updated_at
FROM articles
WHERE category IS NULL
   OR TRIM(category) = ''
   OR category NOT IN (
     'القرآن الكريم وعلومه',
     'التنمية البشرية',
     'الطب التكميلي',
     'الأذكار والاتزان',
     'البحث العلمي',
     'موضوعات معرفية'
   )
ORDER BY updated_at DESC, id;
```

### الاستعلام 5 — فحص تكرار المعرفات والعناوين الحرفية

```sql
SELECT id, COUNT(*) AS copies
FROM articles
GROUP BY id
HAVING COUNT(*) > 1;

SELECT title, COUNT(*) AS copies
FROM articles
GROUP BY title
HAVING COUNT(*) > 1
ORDER BY copies DESC, title;
```

ملاحظة: فحص العناوين هنا حرفي فقط؛ لا يكشف كل صور التشابه بعد إزالة التشكيل أو اختلاف الهمزات أو الرموز.

### الاستعلام 6 — ملخص جدول سجل الإدارة (إن كان الجدول موجودًا)

قبل تشغيله، تحقق من وجود الجدول عبر قائمة الجداول أو الاستعلام التالي:

```sql
SELECT name FROM sqlite_master WHERE type = 'table' AND name = 'article_admin_audit';
```

```sql
SELECT action, COUNT(*) AS event_count,
       MIN(created_at) AS first_event,
       MAX(created_at) AS last_event
FROM article_admin_audit
GROUP BY action
ORDER BY action;
```

إذا لم يكن جدول `article_admin_audit` موجودًا، سجّل ذلك كحالة بنيوية ولا تنشئه أثناء مرحلة الجرد.

## 4. نموذج ملف خريطة التحويل بعد استلام النتائج

يُنشأ صف مستقل لكل سجل فعلي، وتكون الحقول:

| الحقل | الغرض |
|---|---|
| `id` | المعرف الأصلي؛ لا يتغير |
| `title` | العنوان الأصلي |
| `old_category` | قيمة التصنيف الحالية كما هي |
| `proposed_section` | القسم المقترح من الأقسام السبعة |
| `proposed_specialty` | التخصص المقترح من التخصصات الأربعة عشر |
| `content_type` | مقال / بحث / دراسة / مرجع / مادة تعليمية |
| `decision_reason` | سبب التصنيف مع الاستناد إلى محتوى المادة |
| `review_status` | مؤكد / بحاجة لمراجعة / غير محسوم |
| `reviewer` | المراجع المختص |
| `notes` | ملاحظات ومخاطر أو تحفظات |

لا يُصنّف أي سجل اعتمادًا على عنوانه وحده. يجب قراءة المحتوى، والتحقق من موضوعه الأساسي، وتوثيق سبب القرار. المواد الشرعية والصحية والنفسية والبحثية الملتبسة تحال إلى المراجع المختص.

## 5. قواعد الحفاظ على البيانات

- لا تغيير لأي `id` أو عنوان أو محتوى أو تاريخ أو رابط أثناء الجرد.
- لا UPDATE أو INSERT أو DELETE أو ALTER أو CREATE أو DROP في مرحلة القراءة.
- لا تحويل جماعي آلي للقيم القديمة إلى الأقسام الجديدة.
- لا اعتبار «البحث العلمي» نوع محتوى بديلًا عن القسم الموضوعي.
- لا نقل مادة إلى «الحديث الشريف وعلومه» لمجرد ورود حديث مقتبس داخلها؛ يجب أن يكون الحديث/السنة موضوعها الأصلي.
- احتفظ بنسخة نتائج خام مؤرخة قبل إعداد أي اقتراح تصنيف.
- لا يبدأ تصميم migration قبل مطابقة نتائج الجرد بمخطط D1 الحي واعتماد خريطة التحويل.

## 6. ما يلزم لإغلاق مرحلة الجرد

1. تنفيذ الاستعلامات الستة على `alabqri-db` من جلسة Cloudflare موثوقة.
2. حفظ النتائج الخام مع تاريخ الاستخراج واسم القاعدة.
3. مطابقة عدد السجلات بين الاستعلامات وواجهة الإدارة، مع تفسير الفرق المتوقع بسبب المقالات المجدولة والترشيحات المرجعية.
4. إنشاء خريطة تحويل مادة بمادة.
5. مراجعة الحالات غير المحسومة مع المراجع المختص.
6. اعتماد الخريطة قبل أي تغيير برمجي أو ترحيل.
