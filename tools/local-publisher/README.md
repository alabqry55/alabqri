# أداة الحفظ المحلية لمقالات ALABQRI

تنبيه: هذه الأداة ومسار الحفظ الجديد لن يعملا على الموقع الإنتاجي حتى مراجعة PR #147 ودمجه ونشره بنجاح. لا تنفذ خطوات الحفظ قبل ذلك.

هذه أداة محلية تستخدم جلسة المالك في نافذة متصفح مخصصة لإرسال طلب حفظ من نفس نطاق الموقع إلى مسار الحفظ الجديد /api/articles-publish. يضيف مسارًا خادميًا محدودًا لا ينفذ أي CREATE أو ALTER أو migration؛ يتحقق أولًا من وجود مخطط D1 الحالي.

## حدود الأمان

- تعمل على الموقع الإنتاجي https://alabqri.pages.dev فقط.
- تتطلب جلسة مالك موثقة في نافذة المتصفح بحساب GitHub المالك alabqry55.
- تدعم saveMany فقط عبر /api/articles-publish، وهو مسار إنشاء المقالات فقط.
- ترفض المعرّفات والعناوين الموجودة مسبقًا قبل الإرسال.
- لا تدعم delete أو save (الذي يسمح بالاستبدال) أو seedSchedule.
- لا تقرأ Cookie أو تصدره أو تطبعه أو تمرره إلى Node؛ المتصفح يرفق Cookie HttpOnly تلقائيًا مع طلب same-origin.
- لا تشغّل Wrangler ولا تنفذ نشر Pages أو SQL أو migrations. المسار الخادمي يرفض الحفظ إذا كانت الجداول أو الأعمدة المطلوبة غير موجودة بدل إنشائها.
- تطلب كتابة كلمة «نشر» قبل إرسال طلب الحفظ.
- هذه أداة محلية: ChatGPT لا يشغّلها على جهازك. أنت تشغّلها بعد مراجعة ملف المقالات.

## المتطلبات

- Node.js 22 أو أحدث.
- Microsoft Edge أو Google Chrome.
- لا تحتاج إلى تثبيت أي حزمة npm إضافية.

## 1. افتح نافذة متصفح مخصصة

أغلق أي نافذة قديمة تستخدم المنفذ 9222. افتح PowerShell ونفّذ (لمتصفح Edge):

\`\`\`powershell
$profile = "$env:LOCALAPPDATA\ALABQRI-Publisher-Profile"
$edge = "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe"
Start-Process $edge -ArgumentList @("--remote-debugging-port=9222", "--user-data-dir=$profile", "https://alabqri.pages.dev/")
\`\`\`

إذا كان مسار Edge مختلفًا، استخدم مساره الصحيح. لا تستخدم ملف تعريف المتصفح اليومي؛ استخدم ملفًا مخصصًا كما في الأمر.

## 2. سجّل دخول المالك

في نافذة Edge الجديدة:
1. افتح لوحة إدارة المقالات.
2. سجّل الدخول بحساب GitHub المالك alabqry55.
3. تأكد أن أدوات الإدارة ظاهرة وأن الجلسة فعالة.
4. اترك تبويب https://alabqri.pages.dev/ مفتوحًا.

لا ترسل Cookie أو ملف تعريف المتصفح أو أي رمز دخول إلى أي شخص.

## 3. جهّز ملف المقالات

احفظ ملف JSON بترميز UTF-8. مثال مقال واحد للنشر الفوري:

\`\`\`json
{
  "action": "saveMany",
  "articles": [
    {
      "id": "article-example-2026-001",
      "title": "عنوان المقال",
      "category": "التنمية البشرية",
      "date": "26 نوفمبر 2026",
      "excerpt": "ملخص موجز للمقال.",
      "content": "النص الكامل للمقال...",
      "publishImmediately": true,
      "tags": ["التنمية البشرية", "مهارات الحياة"],
      "seoTitle": "عنوان SEO",
      "seoDescription": "وصف SEO",
      "seoKeywords": "كلمات مفتاحية"
    }
  ]
}
\`\`\`

للمقال المجدول، احذف publishImmediately واستخدم scheduledAt بموعد مستقبلي يتضمن المنطقة الزمنية، مثل 2026-12-01T10:00:00+02:00. يمكن إرسال حتى 30 مقالًا في الدفعة؛ يسمح بالنشر الفوري للمقال الأول فقط.

التصنيفات المقبولة:
- القرآن الكريم وعلومه
- الحديث الشريف وعلومه
- التنمية البشرية
- الطب التكميلي
- الأذكار والاتزان
- البحث العلمي
- موضوعات معرفية

## 4. نفّذ الحفظ

من جذر المستودع في Git Bash:

\`\`\`bash
node --version
node tools/local-publisher/publish-articles.cjs ./articles-to-publish.json
\`\`\`

ستعرض الأداة العناوين والمواعيد، ثم تتحقق من جلسة المالك ومن عدم وجود مقال بالمعرّف أو العنوان نفسه. لا يتم الإرسال إلا بعد كتابة «نشر» حرفيًا. ويرسل الطلب إلى /api/articles-publish، وليس إلى مسار المقالات العام.

لا تعتبر العملية ناجحة إلا إذا أعاد الخادم ok: true وverified: true.

## 5. بعد الانتهاء

أغلق نافذة المتصفح المخصصة لإيقاف منفذ التصحيح عن بُعد. لا تترك نافذة النشر مفتوحة عند عدم استخدامها.

## ملاحظة تشغيلية

هذه أداة تساعدك على تشغيل الحفظ محليًا باستخدام جلسة المالك، لكنها لا تمنح ChatGPT وصولًا مباشرًا إلى جهازك. يمكنني تجهيز ملف JSON بالمقال كاملًا، ثم تشغّل أنت أمر الحفظ محليًا وتعيد لي نتيجة الخادم للتحقق منها.
